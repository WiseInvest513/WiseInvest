# 点位观察

## 入口与权限

- `/point`：当前观察、市场与做多/做空方向筛选、搜索、分页及已发布历史。方向可与其他筛选组合，服务端先筛选再计数和分页；普通预览不开放方向筛选。
- `/point/[id]`：参考点位、有效期、一句备注及历史版本。旧记录的观察/失效条件仍可展开查看。
- `/admin/point`：仅管理员可搜索、确认标的及管理计划。
- 导航「内容 → 点位观察」可访问前台。

服务器读取当前数据库中的用户角色和会员等级。`VIP`、`VIP_PLUS` 和管理员可读取完整内容。未登录与普通会员只能读取固定最新三条已发布记录的名称、代码、时间和独立公开摘要（最多 80 字）；搜索、分页和直接访问 ID 不会扩展预览范围。草稿及草稿历史不向会员公开。

新计划的公开摘要由服务端生成固定的会员提示，不从私有备注或点位截取。已有记录独立填写的摘要继续保留。API 和服务端渲染使用同一正向字段白名单，敏感内容不会先下发再遮挡。

## 发布流程与留痕

1. 搜索 Binance 官方合约目录，核对完整 Symbol、名称、类型、计价及结算资产，明确点击确认。
2. 每条计划选择做多或做空；填写入场参考、止损、止盈、一句备注和北京时间有效期。可明确填写一个参考区间，不会自动推算区间。无需另填入场条件、失效条件、公开摘要和修改原因。
3. 保存草稿，或发布。发布前再次校验标的，不根据用户输入自行拼接交易代码。
4. 每次变更自动记录操作名称、时间和版本，以版本号比较并原子保存最新记录和历史快照。兼容旧客户端显式填写的原因。冲突返回 409，管理员需加载最新版本。
5. 已发布标的不可更换，首次发布时间与首次参考价保持不变。撤回、结束、过期记录保留；历史表数据库触发器禁止修改和删除。

过期是由 `validUntil` 计算的展示状态，无需定时删除或定时改库。已撤回或已结束的记录为只读。草稿允许修订，但正式发布后的旧草稿不会追溯暴露给会员。

## 行情

- 来源：`https://fapi.binance.com`。
- `/fapi/v1/exchangeInfo`：产品目录，搜索缓存 15 分钟，发布核验缓存最长 60 秒。
- `/fapi/v2/ticker/price`：最新成交价，服务端缓存及前台轮询约 5 分钟。页面隐藏时暂停请求，返回页面重新获取。
- 支持官方目录内当前 `TRADING` 的 USDT 结算 `PERPETUAL` / `TRADIFI_PERPETUAL`。美股指关联永续合约，不是美股现货报价。
- 行情代理仅向 VIP 开放，限定已有发布记录中的标的，每批最多 50 个。缓存仅存公共行情，不缓存会员记录或身份。
- 管理员编辑器使用独立的 `/api/admin/point/quotes`，仅管理员可调用。确认产品后即可读取官方行情，无需先发布计划；同样限制每批 50 个精确代码，不接受自定义 URL。
- 当前缓存为有界进程内缓存，包含并发去重、超时及限流退避。多实例各有缓存，并非跨服务器共享缓存。
- 源行情时间和获取时间独立保存；不伪造时间或价格。超过 5 分钟标记延迟，超过 24 小时不继续展示旧价格。无有效行情时不推导观察状态。
- 金额用十进制字符串储存、展示与比较，避免浮点舍入造成错误状态。

5 分钟采样不能证明中间曾触价。状态只描述当前采样价相对参考位的位置，不自动宣称入场、成交、止盈、止损或计算收益。没有下单、通知或 K 线功能。

## 本地调试

先进入 `/dev/preview` 选择普通会员、VIP 或管理员，再访问上述入口。点位功能使用独立的内存演示库，即使设置了 `DATABASE_URL`，演示写入也不会落入真实库；重启进程后恢复初始演示数据。前台演示价格显式标记 DEMO，不能作为真实行情。管理员编辑器的参考行情单独访问官方接口，用于核验连接，失败时不以演示价格补齐；计划内容和保存仍完全隔离。

若本机不能直连 Binance，可用现有 `npm run dev:proxy`，或设置服务端 `POINT_HTTPS_PROXY=http://127.0.0.1:7897` 后启动。行情请求现在显式使用 HTTP CONNECT 代理：依次读取 `POINT_HTTPS_PROXY`、`https_proxy`、`HTTPS_PROXY`、`http_proxy`、`HTTP_PROXY`，未配置则直连。代理地址仅从服务器环境读取，不向浏览器输出，不硬编码进应用。云服务器使用其自身可访问的网络或代理，不要照搬本机地址。

网络请求仅允许固定的币安官方产品/报价路径，保留 TLS 校验，禁止重定向，响应最多 4 MiB，超时会中止代理连接；不使用测试网数据替代正式行情。

生产环境完全禁用演示身份和数据。

```sh
npm run point:test
npx tsc --noEmit
npm run prisma:validate
```

## 上线准备

本功能的迁移为 `prisma/migrations/20260920000000_point_plans/migration.sql`。部署时在目标数据库执行既有 `npm run prisma:migrate:deploy`，再发布包含已生成 Prisma Client 的应用。未应用迁移时，前台显示服务暂不可用，不会填充演示记录。

云服务器必须可以访问 Binance 官方 API。上线验收需要实际核对 BTC、MU、INTC 等候选产品和报价；产品以当时官方目录为准，未上线或不可交易的合约不可发布。单元测试使用注入的官方响应格式，不替代生产网络连通性核验。

如果需要跨实例共享缓存、主动提醒、成交追踪或自动交易，必须作为独立需求设计，不能由本功能的采样状态推断。
