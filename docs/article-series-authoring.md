# Wise 系列文章生产约定

## 一、系列是组织方式，不是统一套成教程

复用现有文章与系列阅读页，不复制一套内容模型。`lib/article-library.ts` 是系列信息的唯一入口，正文仍是独立 Markdown 文章。

- `kind: "tutorial"`（或省略）：有先后依赖的教程，用“章 / 学习”。
- `kind: "topic"`：可独立阅读的专题，用“篇 / 阅读”；可用于平台问题、产品介绍、政策解读、研究更新等。
- `kind: "path"`：按用户目标组织的学习路线，使用 `stages` 定义阶段、`chapters[].stageId` 归组。阶段内可按需选读，不把不同平台当作必须依次开户的任务。
- `description` 用一句话说清读者为什么读；可选 `introduction` 解释覆盖范围，不重复广告口号。
- `chapters` 的顺序决定阅读顺序。真实文章保存后才填 `articleId`；未写内容只有 `title`，界面显示“待更新”，没有链接。
- `status: "planned"` 表示规划；已有独立文章则为 `"updating"`。不要把综合旧文重复挂成多个已完成章节。
- 当前阅读器只在 URL 带有效 `?series=<series-id>` 时显示系列侧栏；用 `getSeriesArticleHref` 生成上下文链接，正文也可以链接系列概览。

### 学习路线与资金地图联动

- 新正文仍按原约定独立发布，再把稳定的 `articleId` 加入对应路线的 `chapters`；一篇文章可被多条路线引用，不复制正文。同一路线内不重复挂同一篇综合教程冒充多篇成稿。
- `stages` 的顺序决定阶段顺序，阶段内文章是选项；阅读页提供“同阶段其他文章”和“下一阶段”，下一阶段返回目录供读者选择。
- `mapRouteIds` 只能填写 `CapitalFlowMap` 中已有的路线 ID。同一地图路线只关联一个主系列；没有主系列时，地图仅展示节点对应的已有相关文章。
- 从地图进入文章时保留 `series` 与合法的 `route` 参数；系列链接用 `getSeriesOverviewHref` / `getSeriesArticleHref` 生成，返回地图保留原路线。未知或不匹配的路线回退到该系列的默认地图路线。
- 书籍等非文章资源放在 `stages[].resources`，不计入文章数量。纳指路线首阶段引用 `/book/nasdaq`；不把蓝皮书复制成新正文。
- 本版不导入 YouTube，不把视频链接当作独立图文章节；文章已有视频链接保持原状。只声明实际覆盖范围，不暗示所有资金通道均可办理或已写齐。
- 系列仅组织内容，不改变原文章或地图的访问权限；目录不得向客户端传递受限正文。

## 二、共同写作风格

开头先回答读者的问题，尤其是不适用、不能办理、需要付出成本的条件。不要先铺品牌背景或邀请码广告。

用“你现在是什么情况 → 为什么 → 接下来怎么判断”的自然顺序。句子直接，术语第一次出现时解释；不伪造作者的实测经历、到账速度或客服保证。

正文结构按题目选择，而不是每篇都套相同的六个标题：

| 内容类型 | 核心顺序 |
| --- | --- |
| 问题处理 | 直接结论 → 自查 → 按情况处理 → 生效确认与失败处理 |
| 操作教程 | 适用对象与准备 → 实际步骤 → 结果验证 → 常见问题 |
| 产品介绍 | 解决什么问题 → 如何使用/运作 → 费用与限制 → 哪类人适合 |
| 政策说明 | 哪项规则变化 → 影响谁 → 时间与门槛 → 需要做什么 |
| 研究或观点 | 具体问题 → 证据与解释 → 判断边界 → 后续观察项 |

不为了统一排版硬凑章节、表格、FAQ 或引流段落。邀请码和联盟关系应透明说明，不能用未核实的权益吸引操作。

本次交易所邀请码补填系列的正文不放交易所外链，包括帮助中心引用、自助办理链接和邀请链接。用纯文字讲清条件、操作路径和获取入口的方法，保留必要的站内系列导航即可。官方证据和 URL 留在编辑文档的事实卡中，不堆进读者正文；不因为去掉链接而删除关键限制或佣金关系说明。

## 三、每篇生成前必须准备的事实卡

每个平台单独核实，不继承上一篇的数字或可办理结论。内部记录这些字段：

```text
seriesId / articleId / kind / categoryId
标题 / 一句话问题 / 目标读者
首屏结论 / 不适用对象
原邀请关系能否改变
每条路径的资格（时间、交易、KYC、地区、主/子账户）
官方入口 / 邀请链接或代码及其来源
提交后生效要求 / 如何查结果 / 失败怎么办
费用与风险 / 佣金关系说明
每条关键结论的官方来源 URL / 核验日期
截图来源 / 需要遮挡的个人信息 / 尚未提供的素材
```

优先平台官方帮助中心、条款与活动页。平台社区作者发帖不等于官方规则。数字要分清“低于/不超过”“90 天/三个月”“申请后/绑定后”“成交量/本金/入金”。

无法核实的路径不要发明；登录后才能确定的资格要注明由本人账户核验。没有真实截图时提供可用文字说明，把待补素材记在编辑文档，不向正文插入空图片或生成仿真操作界面。

## 四、可复用的生产提示词

```text
为 Wise 网站写一篇系列文章。先读取本仓库 docs/article-series-authoring.md，
按当前网站已批准的文章风格写作，复用系列组件，不重新设计阅读页。

系列：{seriesId / title / kind}
本篇：{articleId / title / categoryId / 核心问题}
目标读者：{读者已有基础、使用场景}
已确认材料：{用户信息、真实截图、产品入口、邀请代码}
参考：{指定的已有文章或风格样本}

先核验事实卡中的关键规则，记录官方来源与核验日期。
先给结论，前置限制与成本；不得把用户设想当事实，不复制其他平台条件。
选择最适合题目的正文结构，语言直接、解释必要术语，不编造个人使用经历。
规则不清时明确适用边界，缺图时记录待补，不生成伪造界面。
写入独立 Markdown；元数据与封面、系列映射分开管理。
只有真实成稿才能绑定 articleId；未完成的篇目保持待更新。
新增封面遵守 docs/article-covers.md，只给列表使用，不插入正文。
平台主题封面使用仓库中该平台的真实 Logo 作为主要视觉识别，配合品牌色，
不要只替换标题、重复使用同一套账户卡片等通用道具。保留 Wise 银白视觉与右上角小标识。
交易所邀请码补填系列的正文不放交易所外链；来源 URL 留在内部事实卡。
保持既有访问权限，不因系列而放开旧文章或预加载被锁定正文。
完成事实检查、内容/路由/系列单测、类型检查和桌面/手机阅读验证。
未经当前用户明确要求，不创建自动化、不自动提交或部署。
```

## 五、落盘约定

正文示例（当前解析器只支持单行键值，不要放数组或嵌套 YAML）：

```yaml
---
id: stable-article-id
title: 回答一个具体问题的标题
categoryId: crypto
date: YYYY-MM-DD
readTime: 8
summary: 一两句话说明结论、覆盖范围与关键限制。
---
```

1. 保存 `content/articles/<category>/<article-id>/<article-id>.md`，不要修改旧文章的稳定 ID。
2. 列表封面放 `public/images/articles/covers/<article-id>.webp`，通过 `lib/article-covers.ts` 映射；原稿放非公开 `assets/source-images/article-covers/`。
3. 在 `lib/article-library.ts` 绑定真实 `articleId`。路由由 `getArticleRoute` / `genUid` 生成，不用标题作 URL。
4. 新文章沿用默认 MEMBER 阅读规则。若当前用户明确指定公开/VIP，在 `lib/content-access-rules.ts` 中配置；frontmatter 的 `access` 字段不生效。数据库规则仍可能覆盖文件默认规则。
5. 同步旧入口中会与新文冲突的说明，不大范围重写无关平台。
6. 执行相关测试；检查首屏结论、目录、待更新不可点击、系列上下篇、权限、图片体积和手机换行。

本约定是生成模板，不是已创建的定时任务。
