银行已经开好，券商也审核通过，第一次入金却仍可能卡在几个字段：为什么收款人是券商公司？银行账号和证券账号填哪一个？“同名”是不是要求所有名字都一样？

先把角色分清，再填写指令。下面使用文字代号解释资料关系，不提供真实收款账号；实际操作只能使用本人账户当前生成的入金指引。

## 一、先看券商接受什么，再选择银行的按钮

顺序从接收端开始：在本人券商的入金页面选择准备发送的币种，查看可用方式、收款资料和付款账户要求，再去银行找匹配的功能。

不要先在银行随便选“转账”，然后想办法把券商的资料塞进去。收款行在哪里、使用什么币种、采用本地转账还是跨境电汇，会影响需要填写的字段。

例如香港 FPS 支持港元和人民币，并以全天候方式运行；不能因为账户内有美元，就推断同一个 FPS 入口也可以发送美元。券商支持何种币种和方式，还要看其本人入金指引。[金管局 FPS 说明](https://www.hkma.gov.hk/eng/key-functions/international-financial-centre/financial-market-infrastructure/faster-payment-system-fps/)

同样，eDDA 授权、FPS 转账和电汇不是三个可以随意替换的按钮。授权建立了怎样的扣款关系、是否需要另外发起入金，都应依相应服务流程核对；看到授权成功，不要自己推定资金已转走。

## 二、同名要求，核对的是哪两个人

看一组**虚构角色**：

| 角色 | 教学代号 | 负责什么 |
| --- | --- | --- |
| 付款银行账户持有人 | 用户甲 | 从这个账户实际汇出资金 |
| 收款银行 | 银行乙 | 按指令处理收款 |
| 指引指定的银行收款人 | 券商丙公司 | 可能是券商用于收取客户资金的主体 |
| 最终证券账户持有人 | 用户甲，证券账户代号丁 | 资金最后应记入的客户账户 |

“同名”在这里主要核对付款账户持有人与最终证券账户持有人是否符合券商要求。**银行收款人未必是个人姓名**：如果本人指引明确列的是券商公司，就不能为了看起来“同名”而把收款人改成自己。

这只是其中一种收款结构。某些指引可能提供专属或虚拟账号，实际账户名称与附言要求也可能不同。以 IBKR 的港币说明为例，其流程可能要求使用指定的虚拟账户号；不能把另一种方式的账号照搬过来。[IBKR 港币入出金说明](https://www.interactivebrokers.com/support/faq/content/hkd-deposits-withdrawals-1146099335)

IBKR 的官方问答说明，可以建立多家银行的入金资料，但银行账户应与 IBKR 账户持有人同名，并仍受相应限制。[IBKR 多家银行入金要求](https://www.interactivebrokers.com/support/faq/content/deposit-funds-more-than-one-32653177)

朋友代付、公司账户汇给个人证券账户、联名账户或支付机构代汇，各自涉及不同身份关系，不能仅凭附言写了自己的名字就当作已满足条件。先核对本人账户适用规则；信息不清楚时，把具体账户关系向机构说明后再决定。

## 三、把收款指引分成六组信息

不同银行的表单名称可能不同。不要只按字段所在位置照抄，应先理解它要识别哪个对象。

| 信息组 | 从本人指引取得什么 | 常见误填 |
| --- | --- | --- |
| 资金与方式 | 发送币种、入金方式、金额条件 | 用港币指引发美元，或把本地资料用于另一种通道 |
| 收款银行 | 银行名称、所在地及要求的识别代码 | 把券商办公地址当作银行地址 |
| 银行收款人 | 指定的账户名称及必要地址 | 把券商公司名称擅自改成自己的名字 |
| 收款账号 | 该方式对应的账号或其他收款标识 | 把证券账户编号填进银行账号栏 |
| 客户识别资料 | 指引要求的附言、参考信息或最终入账资料 | 漏填、截断，或照抄朋友的编号 |
| 付款资料与费用 | 实际付款账户信息、费用承担、总扣款与预计净额 | 用本人名字描述实际由他人付款的账户 |

银行代码、SWIFT/BIC、IBAN、路由号码等标识服务于不同结构，不能因为都是一串字符就互换。银行页面要求的字段与指引对不上时，先查银行对应通道的填法，不编造代码或地址凑满表单。

附言也不是随便写一句“投资”。它可能承担客户识别作用。IBKR 的官方说明以其电汇指引为例，介绍了包含证券账户编号及账户名称的 Payment Reference；字符长度不足时有自己的处理要求。这种缩写办法只适用于该机构说明的情形，不能自动套给所有券商。[IBKR 附言长度限制说明](https://www.interactivebrokers.com/support/faq/content/payment-reference-field-limited-character-77828941)

如果本人的指引提供专属账号并有另一套要求，也不能反过来强加某种通用附言模板。完整核对这一次指引，比记住一套固定收款资料更可靠。

## 四、通知券商与让银行付款，是两次动作

以 IBKR 的普通电汇入金通知为例，创建通知不会自动移动资金；仍要安排银行实际付款。[IBKR 电汇入金通知说明](https://www.ibkrguides.com/clientportal/transferandpay/enterdeposits.htm)

可以把首次填写过程分成三次检查：

**第一次，取得指引。** 在本人券商内选定币种与方式，按要求登记预计入金信息，保存当前指引及生成时间。不要从群聊或搜索结果复制收款账号。

**第二次，填写银行。** 将六组信息逐项对照，确认真实付款账户、收款主体、银行账号与必要附言。银行的收款人昵称可能只是自己便于识别的标签，不等于真实收款账户名称。

**第三次，审阅确认页。** 再核对币种、总扣款、预计净到账、费用承担和实际发送资料。如果页面省略了关键字段，应返回详情确认，不能因为前一页填过就假定没有变化。

确认后保存银行交易编号与回单。若银行要求补充真实用途或材料，沿该笔申请处理，不通过换付款人、改写用途或重复提交去试探。

“小额测试”也要符合双方门槛和费用条件。太小可能低于接收要求，固定费用也可能占去明显比例；测试金额应由实际规则决定，不照抄别人的数字。

## 五、从汇出到可用，保留三段证据

银行扣款只回答付款端发生了什么。券商收到并匹配、余额可交易或可提取，需要分别核对。

| 证据 | 记录内容 | 不能替代什么 |
| --- | --- | --- |
| 银行付款记录 | 发送币种、金额、交易编号、收款资料及状态 | 不能替券商证明已记入本人账户 |
| 券商资金记录 | 对应入金、币种、实际金额、待处理或完成状态 | 不能单凭总资产证明所有款项已可用 |
| 可用状态 | 下单或提现所需的余额、币种与适用限制 | 交易可用不代表可立即提走 |

如果券商实收少于银行汇出金额，先检查兑换、途中与收款费用；如果根本没有匹配记录，整理银行编号、日期时区、币种金额和指引信息，再通过官方渠道查款。

重复发一笔，不会自动修正前一笔漏填的附言。联系支持时，应围绕原交易提供证据，问清还缺哪项信息、由哪一端处理。

## 六、三种填错场景，应该停在哪一步

**场景一：**用户甲的证券账户，准备由朋友乙的银行账户付款，附言写甲的证券账号。

附言没有改变实际付款人。先查这种付款关系是否被接受；不能因为能够填写甲的账号，就判断满足同名要求。

**场景二：**本人指引写收款人为券商丙公司，用户把它改成自己的名字，认为这样才叫同名。

应停在确认前，重新对照指引。付款人、指定银行收款人与最终客户是不同角色，不能为了名字一致擅改收款主体。

**场景三：**创建入金通知成功，但银行没有任何付款记录；用户却反复催问券商何时到账。

先检查是否真的发起银行付款。如果采用的是本文说明的普通电汇通知，它本身并没有转钱。若实际选择的是带扣款授权的其他方式，则应查看该方式的执行记录，不能把两种流程混用。

若错误在付款后才发现，保存原指令并立即通过银行或券商官方渠道询问可采取的措施。是否能修改、撤回或退回，取决于实际处理状态，不能承诺一定追回或免收费用。

## 七、下单前留一张入金核对单

这张表自己保存即可，不要把完整银行账户与证件资料公开分享。

| 项目 | 自己应该填出的答案 |
| --- | --- |
| 起点 | 实际付款机构、账户持有人与发送币种 |
| 终点 | 本人券商实体、证券账户及目标币种 |
| 方式 | 本人指引支持的通道，以及银行相匹配的功能 |
| 识别 | 指定银行、收款人、账号和必要附言分别是什么 |
| 成本 | 总扣款、预计净到账、已知费用及未知项 |
| 结果 | 银行编号、券商入账、实际金额和当前可用状态 |

完整说明这些信息后，再进入平台图解，会更容易判断哪个字段能照着找位置、哪个内容必须换成本人的资料。
