读教程时觉得每一步都懂，换成自己的订单，却又不知道余额为什么少了。这很常见：理解一句解释，与独立检查一笔结果，需要不同的练习。

这篇把几份虚构记录交给你。先写自己的答案，再看推导；第二题承接第一题，其余案例独立。全程不需要真钱、账户、钱包连接或签名。

## 一、开始之前，写清这笔钱的用途

先填四句话：这笔钱原本用来做什么，什么时候需要取回，可以承受怎样的损失，哪些生活支出不能受影响。学习交易机制，并不要求把这些钱实际转入平台。[Investor.gov 加密资产投资者教育](https://www.investor.gov/introduction-investing/investing-basics/investment-products/crypto-asset-related-investments)

做一道纯算术题：某人用 2,000 个计价单位买入普通现货，价格下跌 50%，忽略费用后损失 1,000。由此能不能说，“只要我最多能亏 1,000，投入 2,000 就安全”？

**不能。** 50% 是题目设定的跌幅，不是最坏结果的保证。还可能有更大的价格损失，或平台、密钥与退出方面的问题。不能把一个方便计算的场景，悄悄变成风险上限。

同样，写下“跌到某个价格就卖”，不等于一定能在该价成交。实际执行还受到订单类型、流动性和系统状态影响。学习记录应说明哪些是已确认的条件，哪些只是自己的计划。

这一节不推导适合所有人的仓位比例。能在入金前说清资金用途与承受范围，才有条件判断后续操作是否符合自己的需要。

## 二、练习一：部分卖出以后，余额与利润怎么算

假设起始只有 **100 USDT、0 BTC**，没有借款、其他资金流或挂单。所有买卖费率为 0.1%，费用另从 USDT 扣除。

1. 以 80,000 USDT/BTC 买入 0.0005 BTC，全部成交。
2. 后来以 90,000 卖出其中 0.0002 BTC，也全部成交。
3. 剩余 BTC 暂按 90,000 估值，没有继续卖出。

先回答四个问题：现在还有多少 USDT、多少 BTC？账户估值多少？已经实现多少盈亏？还有多少盈亏依赖剩余持仓的价格？

### 先逐笔核对余额

| 动作 | USDT 变化 | 操作后的 USDT | 操作后的 BTC |
| --- | --- | --- | --- |
| 起始 | — | 100 | 0 |
| 买入 | −40 −0.04 | 59.96 | 0.0005 |
| 部分卖出 | ＋18 −0.018 | 77.942 | 0.0003 |

剩余 BTC 估值为 0.0003 × 90,000＝27 USDT。账户估值合计 **77.942＋27＝104.942 USDT**，比起始多 4.942。这个估值还没有扣除未来卖出剩余持仓的费用。

### 再把利润拆开

本题只有一次买入，含费总成本为 40.04 USDT。卖出数量占原持仓的 40%，分摊成本为 40.04 × 40%＝16.016。

已实现盈亏：18 −0.018 −16.016＝**1.966 USDT**。

剩余成本：40.04 −16.016＝24.024 USDT。

未实现盈亏：27 −24.024＝**2.976 USDT**。

两者合计 4.942，与账户估值变化一致。这里的 77.942 是可用 USDT 余额，里面包含没有投入的本金和卖出回款，不能全部叫利润。

## 三、练习二：价格又跌了，已经赚到的钱会变吗

承接第一题。假设你什么都没做，BTC 报价从 90,000 变为 40,000。

USDT 余额仍是 77.942，BTC 仍是 0.0003。剩余持仓估值变为 12 USDT，账户估值为 **89.942 USDT**，相对最初 100 净减少 **10.058 USDT**。

之前那次卖出的已实现盈亏仍为 1.966；剩余持仓的未实现盈亏变为 12 −24.024＝−12.024。合计仍是 −10.058。

因此，“已经卖出一部分并赚到钱”，不能推导为“整个账户已经不可能亏损”。只要还持有资产，就要把剩余数量与价格变化继续列在账上。

再检查一个常见误算：一笔资产从 100 跌到 50，是下跌 50%；从 50 回到 100，需要上涨 100%。百分比的分母变了，不能认为“跌多少百分比，再涨同样百分比就回本”。

## 四、练习三：小额测试为什么也会不入账

这是独立题目，与前两题的 BTC 持仓无关。

发送平台的最低提币额为 5 USDT；输入框表示总扣款，费用从里面扣 1 USDT；接收平台要求净充值至少 20 USDT。假设其他资格、币种和网络条件都已满足，余额足够。

输入 20 USDT 做测试，是否满足接收门槛？

**不满足。** 预计接收数量是 19 USDT。按本题条件，输入 21，扣 1 后净收到 20，才达到接收门槛。实际操作仍应重新检查确认页，不把本题费用当作平台报价。

再增加一个条件：接收端只支持网络 X，发送端默认选的是网络 Y，两边地址看起来一样。是否可以因为刚算对金额就发送？

仍然不能。金额计算正确，不会替你解决网络不匹配。先确认双方共同支持的网络和代币版本；没有共同路径时停下，不用一次普通提币尝试跨链。

## 五、练习四：成功记录能证明谁收到什么

题目给出一张虚构的 Ethereum 交易详情：

| 字段 | 内容 |
| --- | --- |
| Status | Success |
| Interacted With | 合约 C |
| Value | 0 ETH |
| Token Transfers | 合约 C 对应代币，地址 A → 地址 B，23 个 |
| Transaction Fee | 0.0008 ETH |

你希望收款到地址 D。对方说：“已经成功，费用也付了，Value 为零只是网页显示问题。”

先写下自己的判断，再看答案。

- Value 为 0 ETH，不足以证明没转代币，本题另有 23 个代币的记录。
- 接收方显示 B，没有证明 D 收到了这一笔。应核对完整地址与原订单。
- 合约 C 是交互对象，不应把它当作自己的收款地址。
- 0.0008 ETH 是网络费，不是 23 个代币中的扣款，也不是对方支付给自己的钱。
- 即使 B 恰好是正确地址，还需要核对网络、合约身份以及必要的平台记账条件。

这道题的关键是找出证据缺口。看到一个绿色成功，就跳过地址和资产身份，后面的金额算得再准也没用。

## 六、练习五：登录、授权与收款能否混在一起

**场景 A：**只想登录一个网站，钱包却要求批准某稳定币的无限额度。

这项权限与当前目的不一致。先拒绝，核对来源和请求内容，不能用“只是登录”替它解释。

**场景 B：**想兑换 20 个代币，授权额度也为 20，但合约对象和网络无法确认。

额度相符只满足一个条件。请求给谁、作用于什么网络和资产仍不明确，还不能批准。

**场景 C：**P2P 买方发来成功截图，但自己的收款账户没有入账，对方要求先释放资产。

截图不能替代自己的真实收款记录。留在原订单里核对和申诉，不能把催促或倒计时当作到账证据。

**场景 D：**钱包收到陌生代币，备注让你去网站输入助记词，称可以兑换奖励。

收到某个代币不代表它有可靠价值，处理收款也不需要提交助记词。不要沿陌生备注交出控制权。

## 七、按错题回看，再留一份自己的操作记录

不要只给自己一个总分。把错误分成三类：数字算错、字段认错、条件未确认。它们需要不同的补课方式。

| 卡住的位置 | 应回看的内容 |
| --- | --- |
| 不清楚花了什么、收到什么 | [第一笔现货买卖](/articles/crypto/ma48m64c?series=crypto-basics) |
| 把回款、可用余额都当利润 | [成本与盈亏核算](/articles/crypto/IGa4mDO7?series=crypto-basics) |
| 不清楚网络、数量和最低额怎样一起核对 | [转账与到账核对](/articles/crypto/oWHIVCLt?series=crypto-basics) |
| 看不懂哈希、Value 和代币转移 | [链上交易查账](/articles/crypto/mEdwAAcA?series=crypto-basics) |
| 只按按钮名字判断权限 | [钱包授权与防骗](/articles/crypto/gayJJIqO?series=crypto-basics) |

最后可以留一份空白记录，之后每次学习新操作都按实际情况填写：

| 项目 | 自己应填写的内容 |
| --- | --- |
| 目的 | 这次是买卖、转移、收款，还是授予权限 |
| 起始状态 | 资产、数量、所在账户与占用情况 |
| 条件 | 资格、网络、目标对象、最低额与费用 |
| 预期变化 | 预计花出什么、收到什么、剩下什么 |
| 实际结果 | 成交或链上记录、费用、余额与未完成部分 |
| 待解决项 | 哪一份证据还缺失，应该找哪个官方入口 |

算对这些题说明你掌握了相应核对方法，不代表现实操作必然顺利。能明确说出“这里还缺信息，所以暂时无法判断”，也是有价值的学习结果。
